# Архитектура моста v2 — «команда-разработчик»

Цель: превратить мост из последовательного пинг-понга (Claude↔Codex, 1 задача за раз)
в самообучающуюся команду с планом, параллельными воркерами, песочницей и критиком.
Принцип внедрения: **безопасность вперёд, поэтапно, всё проверяемо и обратимо.**

## 6 скачков
1. **Параллельная команда (git worktrees).** Оркестратор бьёт задачу на под-задачи (DAG);
   пул воркеров (несколько Codex) работают ОДНОВРЕМЕННО, каждый в своём worktree (своя
   ветка → нет конфликтов файлов); по готовности — авто-мерж + разрешение конфликтов.
2. **Песочница + критик + тесты.** Работа идёт в изолированном worktree, а не в живом;
   сначала тесты (red-green); независимый критик на ДРУГОЙ модели (Gemini/DeepSeek)
   ревьюит дифф на баги/безопасность; промоут в main — только после тестов+ревью.
3. **План-доска (DAG задач).** Постоянная декомпозиция: эпики→задачи→шаги с зависимостями
   и критериями готовности. Агенты работают против доски; возобновляемо и распараллеливаемо.
4. **Умный роутер моделей + бюджет лимитов.** Выбор самой дешёвой модели, которая
   справляется; эскалация при провале; обучение на исходах; учёт расхода предоплаты/платных API.
5. **Память, знающая код.** Индекс кодовой базы (символы/структура/«где определено»);
   память по проектам (отдельные пространства). Точный recall по коду, не только по диалогу.
6. **Наблюдаемость и связь.** Дашборд: граф задач, тренды метрик, расход лимитов;
   push-уведомления на телефон (закончил / нужен ты / упёрся в гейт).

## Порядок (безопасность — фундамент)
**Фаза 1 — фундамент безопасности (строит Claude/человек, с ревью):**
изолированное исполнение (worktree-песочница) + независимый критик + промоут-по-проверке.
КЛЮЧЕВОЕ: после этого ЛЮБАЯ дальнейшая автономная стройка идёт в песочнице и проверяется
перед попаданием в живое — поэтому всё следующее можно строить смелее.

**Фаза 2 — поверх безопасного фундамента (мост строит сам, ревью по git):**
план-доска (№3), умный роутер+бюджет (№4), код-память (№5).

**Фаза 3 — масштаб:**
параллельный пул воркеров (№1, на worktrees из Фазы 1), дашборд + push (№6).

## Кто что строит
- Рискованное ядро (изоляция, оркестрация, мерж, критик) — Claude, поэтапно, после
  design-прохода (можно прогнать через discuss-режим и зафиксировать в decisions/).
- Аддитивные улучшения (план-доска, роутер, код-память, дашборд) — мост автономно,
  под защитой (parse-check, критик, откат на stable) + ревью пользователя по git-диффу.

## Инварианты безопасности (не нарушать)
- Всё в git, откат на known-good `stable`; `.ps1` с BOM + parse-check.
- Чужой код не импортируем — переписываем своё; install/запуск чужого = SAFETY-гейт.
- Не трогать watchdog/supervisor/.git; секреты не выводить; убивать только свои процессы.

## Статус: где живёт каждый скачок (2026-06-23)
Все 6 скачков реализованы; этот раздел — карта от замысла к живому коду.
1. **Параллельная команда** — `lib/parallel.ps1` (`Invoke-ParallelWorkers`, `Invoke-CodexParallel`,
   каждый воркер в своём worktree через `lib/worktrees.ps1`), `lib/circuit-breaker.ps1`;
   до 20 одновременных драйверов (`config.json` `supervisor.maxConcurrentDrivers=20`).
2. **Песочница + критик + тесты** — per-channel sandbox (`coder.sandboxModeByChannel`,
   дефолт `workspace-write`, `danger-full-access` для отдельных каналов через `settings.json`);
   критик на ДРУГОЙ модели (gemini/deepseek) + canary smoke-гейт (`lib/canary.ps1`);
   в режиме `synthesis` — RedTeam-проход перед Decision Record.
3. **План-доска (DAG)** — бэклог дробится на split-модули (`lib/backlog-*.ps1`); workpack-frontier
   с `touch_set`/serial-single fallback (`lib/backlog-workpack.ps1`); Project Autopilot-coordinator
   превращает план в атомы (`lib/backlog-autopilot.ps1`).
4. **Роутер моделей** — `lib/router.ps1` (`Select-PlannerModel` поверх `Get-PlannerModel`),
   триаж `sonnet` / premium `claude-opus-4-8` (`deepModel`); `claude-fable-5` мёртв (404, удалён 2026-06-13).
5. **Память, знающая код** — `lib/memory.ps1` (Gemini-embeddings `gemini-embedding-001`, `Search-Memory`,
   ночной librarian) + `lib/codemem.ps1` (per-project символьный индекс через AST `ParseFile`).
6. **Наблюдаемость + push** — дашборд `server.ps1` (`/api/live-stream` SSE, `/api/state`, `/api/usage`),
   push в Telegram через `lib/notify.ps1`.
