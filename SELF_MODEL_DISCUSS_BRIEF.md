# DISCUSS-ONLY — Bridge Self-Model (заказ оператора, 2026-06-03)

**Обсудите вместе. В ЭТОМ ходе ничего НЕ реализовывать — только спроектировать. Держите STATUS: DISCUSS пока не закончите проработку.**

## Проблема (корень)
У моста ЕСТЬ память, но НЕТ обязательной свежей **самомодели**, которую он видит в КАЖДОМ рабочем ходе. Он может вспомнить кусок прошлого («чинили watchdog», «есть DecisionContract»), но не обязательно видит целостную картину: «я устроен вот так, мои активные фичи такие, эти модули критичные, эти dormant, эти правила нельзя нарушать».

Факт (проверено): в `Build-Prompt`/`Format-Transcript` инжектятся state, память, skills, anti-skills, recurrence, intent, план — но **feature registry и архитектурное самоописание НЕ инжектятся**. Мост слеп к своему устройству, когда улучшает себя. Плюс registry ведётся вручную и дрейфует.

## Цель
Спроектировать механизм, чтобы мост в каждом turn'е видел актуальную **компактную** модель самого себя: архитектура, активные фичи, dormant/сломанные фичи, safety-инварианты, память, воркеры, аудит, планировщик, DecisionContract, project-autopilot, parallel, known risks.

## Нужно
1. Найти, какие источники self-knowledge УЖЕ есть: `PROJECT_MAP.md`, `BRIDGE_STATUS.md`, `features/registry.json`, `memory/map.md`, `PROJECT_WORKFLOW.md`, `OPERATOR_GUIDE.md`, `SLIMMING_PLAN.md`, `git log`, tests.
2. Определить, что из этого должно попадать в prompt ВСЕГДА, а что только по релевантности.
3. Спроектировать compact **Self-Model Pack** размером 2–4 KB.
4. Спроектировать **refresh-механизм**: когда обновлять self-model (после коммитов, задач, аудита, изменений core-файлов).
5. Спроектировать **drift-check**: как понять, что self-model устарела.
6. НЕ плодить новую параллельную память — переиспользовать typed project memory, feature registry, project-context, existing prompt injection.
7. Дать план реализации **АТОМАМИ** с тестами и acceptance criteria.

## Нельзя
- просто «ещё один документ руками»;
- грузить весь registry / PROJECT_MAP целиком в prompt;
- заменять guard/safety моделью;
- ломать текущий memory recall.

## Ориентир архитектуры (от оператора — не догма, обсудите/улучшите)
- **SelfModel Pack** — генерируется ИЗ РЕАЛЬНОСТИ (registry + docs + память + git + state), не пишется руками.
- **SelfModel Inject** — короткая выжимка в prompt каждого turn'а.
- **SelfModel Refresh** — обновляет Pack после важных изменений.
- **SelfModel Drift Audit** — проверяет, не врёт ли Pack относительно реального кода/состояния.

## Результат обсуждения
Архитектурное предложение (как 4 части устроены и связаны) + **план атомов** (1 файл / 1 проверяемое изменение каждый, с тестами и acceptance). Это пойдёт оператору на архитектурный ревью, затем — поглавно в работу.
