# Механизм градуированной автономии (Increment B)

Мост содержит встроенный механизм _само-развития_: он может автономно брать и исполнять неодобренные идеи из бэклога, не дожидаясь ручного одобрения оператора — но только в рамках жёстко ограниченного «диска» (`selfExecuteTier`) и только для идей с достаточно низким риском.

---

## Диск selfExecuteTier

Настройка `autonomy.selfExecuteTier` в `config.json` управляет тем, что система делает с неодобренными идеями статуса `new` из бэклога.

| Уровень | Поведение |
|---------|-----------|
| `off` | Только одобренные оператором/куратором идеи исполняются. Никакого shadow-логирования. |
| `shadow` | Система вычисляет, какую идею она бы взяла и какой у неё риск-тир, **но ничего не исполняет**. Результат выводится в чат. Значение по умолчанию — безопасное. |
| `green` | Автоматически исполняются идеи с риск-тиром `green` (малый радиус, обратимые). Жёлтые и красные не трогаются. |
| `yellow` | Автоматически исполняются идеи с тиром `green` **и** `yellow` (реальные изменения кода). Красные не трогаются никогда. |

Диск хранится в `config.json → autonomy.selfExecuteTier` и может быть изменён оператором или понижен системой автоматически (см. safety-reflex ниже).

---

## Классификатор риска

Функция `Get-IdeaRiskTier` (`lib/backlog.ps1`) — детерминированный (без LLM) эвристический классификатор, присваивающий каждой идее тир на основе текста.

### Тиры

| Тир | Критерий | Пример |
|-----|----------|--------|
| `red` | Внешний источник (radar/web) **ИЛИ** текст затрагивает безопасность, необратимые операции, финансы | watchdog, secrets, `rm -rf`, billing, password |
| `green` | Явно ограниченный обратимый скоуп: документация, комментарии, опечатки, форматирование, lint, переименование переменной, текст лог-сообщения | «Создать docs/README», «Исправить опечатку в комментарии» |
| `yellow` | Всё остальное — реальное изменение кода | Добавление функции, рефакторинг логики, изменение конфига |

### Ключевые свойства

- **Консервативный по умолчанию**: если ни `red`-, ни `green`-паттерн не совпал → тир `yellow`.  
- **`red` никогда не исполняется** ни на каком уровне диска.  
- Классификация двуязычная (RU + EN) — идеи пишутся на обоих языках.  
- Результат персистируется в бэклоге (`risk_tier`, `risk_reason`, `risk_ts`).

## Safety-reflex: автоматическое понижение диска

Функция `Test-SelfDevSafetyReflex` (`lib/backlog.ps1`) — вторая линия защиты. Она срабатывает **перед каждым авто-выбором** идеи и проверяет: не было ли слишком много регрессов от авто-коммитов?

### Алгоритм

1. Берёт все авто-исполненные коммиты за последние **14 дней** (поле `self_exec_commit` в бэклоге).  
2. Сопоставляет их с 24-часовым вердиктом (поле `verdict`).  
3. Если `≥ 2` вердиктов `worse` → **понижает диск на один шаг**:
   - `yellow` → `green`  
   - `green` → `shadow`  
4. Изменение применяется немедленно (`Set-AutonomySetting`), событие выводится в чат с пометкой 🛡.

### Место в системе защиты

| Линия | Механизм |
|-------|----------|
| 1-я (pre-commit) | smoke-тест + независимый critic — блокируют плохой коммит до его появления |
| 1-я (per-commit) | 24-часовой вердикт — авто-откат при регрессе конкретного коммита |
| 2-я | Safety-reflex — понижает диск, если регрессы накапливаются (система учится быть осторожнее) |

## Поток выполнения (идле-цикл)

```
driver.ps1 → idle tick
  ├─ Test-AutonomyReady?          # Настройки автономии включены?
  ├─ Test-SelfDevSafetyReflex     # Проверить регрессы → понизить диск если нужно
  ├─ Get-NextSelfExecIdea         # Найти первую in-dial идею (green ≤ dial, red исключён)
  ├─ [shadow] → вывести в чат, не исполнять
  └─ [green/yellow] → пометить как auto-claimed → запустить задачу
```

---

## Конфигурация

```json
// config.json → autonomy
{
  "selfExecuteTier": "shadow",   // off | shadow | green | yellow
  "scope": "bridge",             // bridge | projects
  "enabled": true
}
```

Параметры `Test-SelfDevSafetyReflex`:
- `WorseThreshold` = 2 (минимум «worse» вердиктов для срабатывания)
- `LookbackDays` = 14 (окно анализа в днях)
